# 하숙집 맞고 — 하숙생 맞고

바닷가 잔디 언덕 위, 바다 쪽 벽이 통째로 유리인 방 열 개짜리 이층 별장.
할머니는 이 좋은 집을 혼자 쓰지 않고 삼십 년 동안 방을 내줬다 — 「집이 크면 사람이 있어야 해」.
그분이 돌아가시고 주인공 혼자 남았는데, 좋은 집은 가만히 있어도 돈을 먹는다.
그래서 다시 하숙을 놓는다.

방석 밑에서 나온 할머니의 공책에는 하숙 규칙이 세 줄 적혀 있다.
**「하나. 방은 깨끗이. 둘. 밥은 같이. 셋. 밤에는 마루에서 한 판.」**

사연을 하나씩 안고 들어온 하숙생 10명과 각각 10판씩, 총 100판. 이기면 호감 이벤트가 열리고,
10판째를 이기면 그 사람과 사귀게 된다. 마당 끝 별채에는 삼십 년째 나가지 않은 사람이 하나 있다.

**맞고 70% + 연애 비주얼노벨 30%.** 15세 이용가 기준.
승부 화면은 **화면 폭에 따라 세로 판과 가로 판으로 자동 전환**된다 — 폰을 세우면 위아래로 쌓이고,
눕히거나 PC 로 열면 먹은 패·바닥·점수판이 좌우로 펼쳐진 고스톱 판이 된다.

## 실행 방법

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:8795 을 연다. 개발 중에는 휴대폰 크기(375×812)로 보는 것을 권한다.

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm test` | 규칙 엔진 · AI · 시나리오 · 백업 · 경제 테스트 전체 (135개) |
| `node scripts/playtest.mjs` | 100단계 밸런스 시뮬레이션 (시간·승률·포인트 수지) |
| `npm run test:watch` | 테스트 감시 모드 |
| `npm run typecheck` | 타입 검사 |
| `npm run build` | 타입 검사 + 웹 번들 빌드 (`dist/`) |
| `npm run build:h5` | H5(모바일 웹) 빌드 후 `docs/hasukgo/` 에 복사 |
| `npm run cap:sync` | 빌드 후 안드로이드 프로젝트에 반영 |
| `npm run cap:apk` | 로컬에서 디버그 APK 빌드 (JDK 17 + Android SDK 필요) |
| `npm run icons` | 앱/PWA 아이콘 다시 생성 |

## APK 만들기

### 방법 A — GitHub Actions (권장, 이 PC에 아무것도 설치하지 않음)

`.github/workflows/hasukgo-android.yml` 이 이미 들어 있다. `hasukgo/` 아래를 고쳐 push 하면 자동으로 돌고,
Actions 탭에서 **Run workflow** 로 수동 실행도 된다. 완료되면 아티팩트에 `hasukgo-apk`(APK)와 `hasukgo-aab`(Play 업로드용)가 올라온다.

**서명 키를 등록하기 전에는 미서명 빌드**라 스토어에 올릴 수 없다(설치 테스트는 가능).
서명하려면 저장소 Settings → Secrets and variables → Actions 에 네 개를 넣는다.

| 시크릿 | 값 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | 키스토어 파일을 base64로 인코딩한 문자열 |
| `ANDROID_KEYSTORE_PASSWORD` | 키스토어 비밀번호 |
| `ANDROID_KEY_ALIAS` | 키 별칭 |
| `ANDROID_KEY_PASSWORD` | 키 비밀번호 |

키스토어는 본인 PC에서 직접 만든다(비밀번호를 다루는 작업이라 직접 하셔야 한다).

```bash
keytool -genkey -v -keystore release.keystore -alias hasukgo -keyalg RSA -keysize 2048 -validity 10000
base64 -w 0 release.keystore > release.keystore.b64
```

> `release.keystore` 와 비밀번호는 잃어버리면 같은 앱을 다시 업데이트할 수 없다. 별도로 백업해 둘 것.
> 키스토어 파일 자체는 `.gitignore` 에 걸려 있어 커밋되지 않는다.

### 방법 B — 이 PC에서 직접 빌드

JDK 17 과 Android SDK(Platform 35, Build-Tools)를 설치한 뒤:

```bash
npm run cap:apk
```

`android/app/build/outputs/apk/debug/app-debug.apk` 가 나온다.

"모의 도박(simulated gambling)" 항목을 정직하게 체크해야 한다. 이 경우 국가에 따라 12세/15세 이상 등급이 매겨진다.

## H5 (모바일 웹)로 플레이하기

설치 없이 브라우저에서 바로 돌아간다. 서버와 통신하지 않으므로 한 번 열면 오프라인에서도 계속 플레이된다.

```bash
npm run build:h5
```

`docs/hasukgo/` 에 소개 페이지와 게임이 함께 조립된다. 커밋해서 main 에 push 하면 GitHub Pages 가 서빙한다.

| | 주소 | 무엇 |
|---|---|---|
| 소개 | https://netbell23.github.io/stocknews/hasukgo/ | 게임 소개 랜딩 (공유용) |
| 게임 | https://netbell23.github.io/stocknews/hasukgo/play/ | 게임 본체 |

소개 페이지는 `landing/index.html` 템플릿에 `scripts/build-landing.mjs` 가 내용을 채워 만든다.
스크린샷 파일을 따로 두지 않고 **게임이 실제로 쓰는 SVG 아트 생성기를 빌드 시점에 그대로 돌려**
하숙생 입상과 화투패를 페이지에 직접 박아 넣는다. 그래서 아트를 고치면 소개 페이지도 같이 바뀌고,
이미지 자산이 한 개도 없다. 미해금 하숙생은 흑백 + `???` 로 가려 스포일러를 줄였다.
문구를 고치려면 `landing/index.html` 만 건드리면 된다.

경로는 상대 경로(`base: './'`)라 어느 하위 폴더에 올려도 그대로 동작한다. 다른 호스팅(Netlify, S3, 사내 서버)에 올릴 때도
`dist/` 를 통째로 복사하면 된다.

### H5 에서 따로 손본 것들

모바일 브라우저는 데스크톱과 다르게 구는 지점이 많아 `src/h5.ts` 에서 한 번에 잡는다.

| 문제 | 처리 |
|---|---|
| 주소창이 접혔다 펴지며 `100vh` 가 실제 화면보다 커짐 | `visualViewport` 를 읽어 `--app-h` 로 내려주고 CSS 가 이걸 쓴다 |
| 아래로 당기면 새로고침돼서 판이 날아감 | 스크롤 영역이 아닌 곳의 당김 제스처만 취소 |
| 더블탭/핀치 확대로 UI가 깨짐 | `touch-action` + 제스처 취소 |
| 카카오톡·라인 인앱 브라우저 | 감지해서 `data-inapp` 속성으로 표시 (레이아웃 보정용 훅) |
| 홈 화면에 추가 | PWA manifest + iOS 전용 메타 태그 |
| 오프라인 플레이 | 서비스 워커가 첫 방문에 받은 파일을 캐시 |

서비스 워커 캐시 이름은 `npm run build:h5` 가 빌드할 때마다 새 값으로 찍는다. 그래서 새 버전을 올리면
이용자 폰에서 자동으로 갱신된다.

> 서비스 워커는 **HTTPS 에서만 등록된다.** 로컬 http 나 개발용 내장 브라우저에서는 실패하는 것이 정상이고,
> 배포본(https://netbell23.github.io/stocknews/hasukgo/)에서 등록·오프라인 캐시까지 확인했다.
> 첫 방문에는 워커가 활성화되기 전에 JS/CSS 가 이미 내려와 캐시에 안 들어간다. **두 번째 방문부터 오프라인으로 돌아간다.**
> 등록에 실패해도 게임은 그대로 동작한다(오프라인 기능만 빠진다).

## 진행도 저장과 기기 식별

### 왜 폰 고유번호를 쓰지 않았는가

브라우저에는 **IMEI·시리얼번호·MAC 주소를 읽는 API가 아예 없다.** 표준에도 없고 어떤 브라우저도 제공하지 않는다.
Capacitor 네이티브 앱의 `Device.getId()` 도 하드웨어 ID가 아니라 앱 설치마다 새로 생기는 UUID 를 돌려준다.
브라우저 지문(fingerprinting)으로 흉내낼 수는 있지만 Safari·Firefox 가 적극적으로 차단하고,
구글 플레이 정책과 개인정보보호법상 지속적 식별자로 쓰면 문제가 된다.

그래서 **재설정 가능한 기기 ID** 방식을 썼다.

- 첫 실행에 무작위 UUID 를 발급한다. 개인정보를 전혀 담지 않고 어디로도 보내지 않는다.
- 설정 화면에 `HSG-XXXX-XXXX` 형태의 짧은 코드로 보여준다.
- `localStorage` 와 `IndexedDB` 에 이중으로 저장해, 한쪽이 지워져도 다른 쪽에서 되살린다.
- 되살렸을 때는 홈 화면에 알림을 띄운다.

관련 코드: `src/auth/device.ts`

### 백업 코드

서버가 없으므로 진행도 전체를 문자열 하나로 뽑아낸다. 설정 → 진행도 백업에서 복사하거나 파일로 저장한다.

```
HSG1.rZMxb9QwGIb_SvTNThU78SXnDTFUbIhD...(약 700자)....1D3TV4K
```

- 압축(deflate) 후 base64url + 체크섬. 한 글자만 깨져도 거부한다.
- 이 코드를 다른 폰에 붙여넣으면 그대로 이어서 할 수 있다.
- 복원 전에 "무엇을 덮어쓰는지" 요약을 보여주고 확인을 받는다.
- 하숙생이 나중에 추가돼도 옛날 백업 코드를 읽을 수 있다.

관련 코드: `src/save/transfer.ts` / 테스트 `tests/transfer.test.ts`

### 아이폰 사파리 주의

iOS 사파리는 **홈 화면에 추가하지 않은 사이트의 저장 데이터를 일정 기간 뒤 지운다.**
H5 로 오래 즐길 이용자에게는 홈 화면 추가나 백업 코드를 권해야 해서, 설정 화면에도 그 안내를 넣어뒀다.

### 이걸로 할 수 없는 것

이 방식은 **진행도 저장·복구 전용**이다. 아래는 서버 없이는 불가능하다.

- 중복 보상·어뷰징 차단 (기기 ID를 이용자가 초기화할 수 있으므로)
- 기기당 1계정 제한
- 랭킹·업적 같은 공용 데이터

이런 게 필요해지면 서버 + 계정 로그인(카카오/구글) 또는 휴대폰 SMS 인증을 얹어야 한다.

## 포인트 경제

포인트는 맞고 판돈 그대로다. **이기면 내 점수 × 점당, 지면 상대 점수 × 점당 × 0.7.**
고·피박·광박·멍박·고박의 배수가 이미 점수에 실려 있으므로 그대로 판돈이 된다.
그래서 고/스톱이 진짜 갈등이 된다 — 한 번 더 가면 판돈이 커지지만, 뒤집히면 고박으로 두 배를 문다.

| 하숙생 | 점당 | 최소 보유 | 10단계 클리어 보너스 |
|---|---|---|---|
| 은서 | 3P | 30P | 179P |
| 민지 | 10P | 100P | 121P |
| 도희 | 25P | 250P | 211P |
| 윤 | 35P | 350P | 257P |

- **최소 보유 포인트**(점당 × 10)가 없으면 그 하숙생과 붙을 수 없다. 10점짜리 패배를 감당할 수 있어야 자리에 앉는다는 뜻.
- **질 때는 7할만 문다.** 딴 사람이 받는 만큼 다 물리면 잘하는 사람도 결국 마른다.
  이 계수 덕에 자기 수준에 맞는 상대에게는 꾸준히 벌 수 있고, 벅찬 상대에게는 잘해야 본전이 된다.
  클리어를 다 한 뒤에도 만만한 상대로 포인트를 되벌 수 있는 것이 이 계수 때문이다.
- **지더라도 호감도와 단계는 그대로다.** 잃는 것은 포인트뿐이다.
- 클리어 보너스는 단계를 **처음** 깼을 때만 붙는다. 주 수입원은 판돈이다.

승부 중에는 「이기면 +N P · 지면 −N P」가 실시간으로 뜨고, 고/스톱 화면에도 지금 스톱하면 받을 금액이 나온다.

### 상점 — 유일한 소비처

**승부에 유리해지는 물건은 팔지 않는다.** 포인트로 유리함을 사면 "판돈"이라는 설정이 무너진다.
파는 것은 전부 겉모습이다.

| | 품목 | 가격 |
|---|---|---|
| 화패 | 한지 / 달밤 / 금박 | 1,200 / 2,200 / 3,800P |
| 마루 테마 | 툇마루 한낮 / 첫눈 오는 밤 / 등불 | 900 / 1,800 / 2,800P |

전부 12,700P. 화패 스킨은 `src/art/cards.ts` 의 `CARD_SKINS`, 테마는 `src/data/shop.ts` 의 `MARU_THEMES` 에서
색만 바꾸면 추가된다. 도안과 레이아웃은 건드리지 않는다.

### 밸런스 측정

```bash
node scripts/playtest.mjs 200
```

100단계를 숙련도 3종으로 전부 돌려 승률·소요 시간·포인트 수지·이상 징후를 뽑는다.
UI 연출 지연(AI 620ms, 고/스톱 2.1초, 결과 900ms, 타이핑 25ms/자)을 그대로 반영하므로
나오는 시간은 실제 체감과 비슷하다.

| 숙련도 | 100단계 소요 | 완주 시 포인트 | 총 도전 판수 |
|---|---|---|---|
| 초보 | 3시간 15분 | 6,100P | 252판 |
| 보통 | 2시간 56분 | 12,100P | 221판 |
| 숙련 | 2시간 36분 | 15,500P | 196판 |

초보는 상점의 절반쯤을 살 수 있고, 숙련자는 거의 전부를 산다. 더 사려면 반복 플레이가 필요하다.
포인트가 최소 보유액 아래로 떨어지면 홈에 **「어머니께 용돈 받기」**(+100P)가 떠서 완전히 막히지는 않는다.

## 폴더 구조

```
src/
  engine/       규칙 엔진 — 순수 로직. React/DOM 에 전혀 의존하지 않는다.
    types.ts      카드/상태/규칙 옵션 타입
    cards.ts      화투 48장 + 보너스 쌍피 정의
    score.ts      점수 계산 · 박 · 배수 정산
    game.ts       판 진행 상태 머신 (쪽/따닥/뻑/쓸/폭탄/총통)
    rng.ts        시드 난수 (테스트 재현성)
  ai/           AI 모듈
    params.ts     난이도 2차원 곡선 (하숙생 순번 × 단계)
    ai.ts         패 평가 · 고/스톱 판단 · 플레이어 패턴 학습
```

## 아트 교체

캐릭터·배경·화패는 전부 **코드로 생성한 원본 SVG** 다. 기존 게임의 자산은 한 장도 쓰지 않았다.

집과 관련된 배경 여덟 장(`yard beach maru annex kitchen hallway room rooftop`)은 **실사풍**으로
그린다 — 그라디언트로 빛의 기울기를, `feTurbulence` 로 질감을, `feGaussianBlur` 로 그림자를,
하늘색을 섞어 대기 원근을 만든다. 실내는 소실점 하나짜리 상자(`roomBox`)에 가구를 놓는 방식이라
방을 하나 더 만들려면 가구 배치만 쓰면 된다. 이 여덟 장은 `SELF_GRADED` 에 묶여 전역 헤이즈를
건너뛴다 — 창문 불빛까지 어두워지면 밤 장면이 죽기 때문이다.
집 밖 배경(편의점·캠퍼스·골목·축제·역)은 평면 그림 그대로다.

**화투 48장**은 한국 화투의 도안 언어로 그렸다. 도안 자체(송학·매조·만막·공산명월·
국진·비광 …)는 이백 년 된 공유 도상이라 얼마든지 그릴 수 있지만, **제조사나 다른 게임의
그림·스캔은 한 장도 쓰지 않았다.**

한국 화투를 한국 화투로 보이게 하는 건 세 가지다.
1. **굵은 주홍 테두리.** 이게 없으면 일본 하나후다처럼 보인다.
2. **흰 바탕에 큼직한 검은 실루엣.** 면이 크고 선이 적다.
3. **원색 네 가지(주홍·노랑·파랑·초록)만** 점처럼 얹는다.

띠는 가로줄이 아니라 비스듬히 누운 띠다. 스킨(전통/한지/달밤/금박)은 테두리·바탕뿐 아니라
도안의 주홍·노랑까지 같이 갈아입힌다.

하숙생 열 명은 각자 얼굴형·눈매·앞머리·머리 모양·의상 3벌·소품을 따로 갖고 있어
한 줄로 세워도 서로 구분되고, 46px 썸네일에서도 누군지 알아볼 수 있다
(`node scripts/char-sheet.mjs` 로 직접 확인). 표정 8종 × 의상 3종 = 1인당 24종,
열 명이면 **240종이 전부 다르게 그려진다** — `npm test` 가 이걸 검사한다.

원화로 바꾸고 싶으면 파일만 넣으면 된다.

| 종류 | 넣을 위치 | 켜는 법 |
|---|---|---|
| 캐릭터 입상 | `public/art/char/{tenantId}_{outfit}_{expression}.png` | `src/ui/parts.tsx` 의 `IMAGE_FIRST` 를 `true` 로 |
| 배경 | `public/art/bg/{bg}_{time}.jpg` | 같은 파일에서 `Background` 를 수정 |
| 화패 | `public/art/card/{cardId}.png` | 같은 방식 |

`expression` 은 `normal smile sulk surprise shy serious win lose`, `outfit` 은 `0 1 2`.
파일이 없으면 자동으로 SVG 로 되돌아가므로, 한 명씩 순서대로 교체해도 게임이 깨지지 않는다.

캐릭터당 필요한 장수는 **입상 1종 × 표정 8종 × 의상 3종 = 24장**, 10명이면 240장이다.
배경은 13종 × 시간대 3종 = 39장, 엔딩 CG 는 11장(하숙생 10 + 히든 1).

앱 아이콘은 `node scripts/gen-icons.mjs` 로 다시 생성한다.

## 판의 연출

맞고는 손맛으로 하는 놀이라 판이 조용하면 재미가 없다. 네 가지를 넣었다.

- **상대 손패는 뒷면으로만 보인다.** 장수는 알 수 있고 무슨 패인지는 모른다.
  (먹은 패는 광/띠/열/피로 나뉘어 공개된다 — 점수를 읽어야 하니까)
- **바닥패는 겹치지 않고 펼쳐진다.** 겹쳐 쌓으면 뒤 패의 도안이 가려져 뭘 먹을지 안 보인다.
- **손패를 누르고 있으면** 그 패로 먹을 수 있는 바닥패가 떠오르며 금빛 테를 두른다.
- **패를 낼 때마다 판이 한 번 울린다**(`.felt.slam`). 쪽·따닥·뻑·쓸은 화면 폭의 22% 크기로
  터지고 붉은 섬광과 퍼지는 고리가 같이 나간다.
- **같은 월이 바닥에 두 장이라 골라야 할 때**는, 맞출 패를 가운데에 세워 보여주고
  후보 두 장만 띄워 금테와 ▼ 표시를 붙인다. 나머지 바닥패는 눌러 둔다.
  (전에는 후보 표시가 없어서 판이 멈춘 것처럼 보였다)

### 카드가 실제로 움직인다 — `useCardFlight`

규칙 엔진은 동기 함수라 한 번의 setState 로 "냈다 → 먹었다 → 내 더미로 갔다"가 전부
끝나 있다. 중간 과정을 따로 만들지 않고 **FLIP** 으로 되돌려 보여준다 — 그리기 직전에
모든 카드 위치를 재두고(First), 리액트가 새 자리에 그리면(Last), 옛 자리로 되돌리는
변형을 걸어(Invert) 0 으로 푼다(Play). 카드마다 `data-cid`·`data-zone` 만 달면 된다.

연출 순서는 delay 로 만든다.
- **손 → 바닥**: 0.28초, 던지는 방향으로 회전하며 날아가 살짝 튀며 앉는다
- **더미 → 바닥**: 0.34초, 더미 자리에서 `rotateY` 로 뒤집히며 나온다
- **바닥 → 먹은 패**: 0.23초 기다렸다가(바닥에 붙어 있는 것처럼 보인다) 한 번 커졌다 쑉
- **자리만 밀린 패**: 0.2초 미끄러지기만. 이걸 구분하지 않으면 한 수에 판 전체가 요동친다

손패는 올리면 뜨고 누르면 확실히 들린다. 먹은 장수는 오를 때 한 번 튄다.

## 난이도 설계

하숙생 순번(1~10)과 단계(1~10)의 **2차원 곡선**이다. 순번 가중 0.6, 단계 가중 0.4.

- **1번 1단계**: 실수율 50%, 추론 0
- **10번 10단계**: 실수율 0%, 추론 최대 + 플레이어 최근 20판 패턴 학습

패턴 학습은 최상위 구간에서만 켜진다. 플레이어가 고를 자주 하는지, 어떤 항목(광/열끗/띠/피)을
주로 모으는지를 최근 20판에서 뽑아 견제에 쓴다.

AI 대 AI 400~1000판 시뮬레이션으로 검증한 실제 승률:

| 대결 | 승률 |
|---|---|
| 1번 1단계 vs 10번 10단계 | 33% : **67%** |
| 1번 1단계 vs 5번 5단계 | 44% : 56% |
| 5번 5단계 vs 10번 10단계 | 39% : 62% |
| 같은 난이도끼리 | 49% : 51% |

맞고는 배분 운이 크게 작용하는 게임이라 최고 난이도에서도 2:1 정도가 한계다.
그 대신 같은 하숙생이라도 단계가 오르면 눈에 띄게 강해지고, 대사도 "요즘 연습했다"는 톤으로 바뀐다.
`npm test` 의 `tests/balance.report.test.ts` 가 이 표를 매번 다시 뽑는다.

## 진행 구조

첫 실행에는 `world` 씬(세계관)이 먼저 나오고 그다음 `prologue` 가 이어진다.
둘 다 `src/data/scripts/common.txt` 에 있고, 재생 순서는 `src/App.tsx` 의 `nextCommonScene` 이 정한다.

- 처음엔 1~3번만 열려 있고, **앞 순번 하숙생의 5단계를 클리어하면** 다음 사람이 열린다.
  윤(최종 히로인)은 예린·세연·도희 세 명의 5단계를 모두 거쳐야 열린다.
- 단계 클리어당 호감도 +10, 이벤트에서 추가로 +10
- **지면 호감도가 깎이지 않는다.** 포인트만 잃고 다시 도전할 수 있다.
- 3연패하면 해당 하숙생이 힌트 대사를 준다 ("나 요즘 띠만 모으는 거 알지?")
- 전원 10단계 클리어 시 히든 엔딩(마루 단체 사진)

## 세계관

- 무대는 **바닷가 언덕 위 고급 별장** 한 채다. 통유리 거실, 원목 데크, 방 열 개.
  할머니가 이 집에서 삼십 년 하숙을 쳤고("집이 크면 사람이 있어야 해"), 돌아가신 뒤
  주인공이 물려받아 혼자 산다. 재산세와 관리비를 혼자 감당 못 해 다시 하숙을 놓는다.
  비싼 집에 「하숙」 나무 간판이 걸려 있는 게 이 집의 농담이자 정체성이다.
- **하숙생 열 명은 각자 이 집에 온 이유가 있다.** `tenants.json` 의 `backstory` 에 한 줄로 적혀 있고
  도감 프로필의 「이 집에 온 이유」에 표시된다. 10단계 이벤트가 그 사연을 풀어가는 구조다.
- **마루의 화투 규칙**은 할머니가 남긴 것이다. 서로 말도 못 붙이던 하숙생들을 마주 앉히려고
  만든 규칙이라는 게 윤의 이야기(`yoon_02`)에서 밝혀진다.
- **별채의 윤**이 최종 히로인이자 히든 스토리의 축이다. 삼십 년 전 사라진 광 한 장을 기다리고 있고,
  그 내력은 할머니의 옛 장부에서 나온다(`yoon_06`).
- 할머니는 이야기 시작 시점에 이미 고인이다. **살아 있는 어머니는 등장하지 않는다** —
  설정이 어긋나지 않도록 `npm test` 가 스크립트 전체에서 검사한다.

## 톤과 수위

- 등장인물 전원 성인 (22~29세), 15세 이용가 기준의 로맨스 코미디
- 노출·성적 묘사 없음, 도박 미화 없음, 현금 판돈 없음
- **연애는 승부에서 이겨서 "얻는" 것이 아니다.** 승부를 계기로 서로 알아가다 상호 호감으로 이어지는 구조이고,
  모든 10단계 고백 대사에 "이겨서 받는 상이 아니다"라는 취지가 명시돼 있다.
- 지면 하숙생이 실망하는 게 아니라 다음 승부를 기대하는 톤으로 쓰여 있다.

## 알려진 한계

- 아트는 코드로 그린 평면 SVG 다. 열 명이 구분되고 표정·의상이 전부 다르게 나오지만,
  손으로 그린 일러스트의 질감은 아니다. `public/art/char/` 에 원화를 넣으면 그대로 교체된다.
- BGM/효과음은 태그만 스크립트에 들어가 있고 실제 음원은 없다. `ScenarioView.bgm` / `sfx` 를 읽어 재생기를 붙이면 된다.
- 상점은 포인트로만 산다. 현금 결제 연동은 없다(광고 보상도 아직).
- APK 빌드는 GitHub Actions 에서 검증해야 한다. 이 저장소에서 아직 워크플로를 한 번도 돌리지 않았다면
  첫 실행에서 툴체인 문제가 나올 수 있다(AGP 8.7.2 / Gradle 8.9 / JDK 17 / compileSdk 35 조합으로 맞춰뒀다).
