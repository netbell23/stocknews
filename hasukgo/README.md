# 하숙집 맞고 — 하숙생 맞고

서울의 한 하숙집. 어머니가 운영하는 이 집의 오랜 전통은 **밤마다 마루에서 벌어지는 맞고 승부**다.
개성 강한 하숙생 10명과 각각 10판씩, 총 100판. 이기면 호감 이벤트가 열리고, 10판째를 이기면 그 사람과 사귀게 된다.

**맞고 70% + 연애 비주얼노벨 30%.** 세로 모드 모바일 우선(390×844), 15세 이용가 기준.

---

## 실행 방법

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:8795 을 연다. 개발 중에는 휴대폰 크기(375×812)로 보는 것을 권한다.

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm test` | 규칙 엔진 · AI · 시나리오 · 백업 테스트 전체 (118개) |
| `npm run test:watch` | 테스트 감시 모드 |

| `npm run build:h5` | H5(모바일 웹) 빌드 후 `docs/hasukgo/` 에 복사 |

## APK 만들기

### 방법 A — GitHub Actions (권장, 이 PC에 아무것도 설치하지 않음)

`.github/workflows/hasukgo-android.yml` 이 이미 들어 있다. `hasukgo/` 아래를 고쳐 push 하면 자동으로 돌고,
Actions 탭에서 **Run workflow** 로 수동 실행도 된다. 완료되면 아티팩트에 `hasukgo-apk`(APK)와 `hasukgo-aab`(Play 업로드용)가 올라온다.

**서명 키를 등록하기 전에는 미서명 빌드**라 스토어에 올릴 수 없다(설치 테스트는 가능).
서명하려면 저장소 Settings → Secrets and variables → Actions 에 네 개를 넣는다.

| 시크릿 | 값 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | 키스토어 파일을 base64로 인코딩한 문자열 |
| `ANDROID_KEYSTORE_PASSWORD` | 키스토어 비밀번호 |
| `ANDROID_KEY_ALIAS` | 키 별칭 |
| `ANDROID_KEY_PASSWORD` | 키 비밀번호 |

키스토어는 본인 PC에서 직접 만든다(비밀번호를 다루는 작업이라 직접 하셔야 한다).

```bash
keytool -genkey -v -keystore release.keystore -alias hasukgo -keyalg RSA -keysize 2048 -validity 10000
base64 -w 0 release.keystore > release.keystore.b64
```

> `release.keystore` 와 비밀번호는 잃어버리면 같은 앱을 다시 업데이트할 수 없다. 별도로 백업해 둘 것.
> 키스토어 파일 자체는 `.gitignore` 에 걸려 있어 커밋되지 않는다.

### 방법 B — 이 PC에서 직접 빌드

JDK 17 과 Android SDK(Platform 35, Build-Tools)를 설치한 뒤:

```bash
npm run cap:apk
```

`android/app/build/outputs/apk/debug/app-debug.apk` 가 나온다.

### 구글 플레이 관련 설정 현황

| 항목 | 값 |
|---|---|
| 패키지명 | `com.storytaco.hasukgo` |
| compileSdk / targetSdk | 35 (2025년 신규 앱 요건) |
| minSdk | 22 (Android 5.1) |
| 화면 방향 | 세로 고정 |
| 권한 | `INTERNET` (Capacitor 기본값. 게임은 완전 오프라인이라 지워도 동작한다) |
| 스토어 아이콘 | `store/icon-512.png` |

심사 관련 메모: **현금 판돈·환전·구매 요소가 없다.** 판돈은 설거지 면제권 같은 "하숙집 포인트"이고,
설정 화면 하단에도 그 문구를 표시한다. 다만 화투를 소재로 쓰므로 콘텐츠 등급 설문에서
"모의 도박(simulated gambling)" 항목을 정직하게 체크해야 한다. 이 경우 국가에 따라 12세/15세 이상 등급이 매겨진다.

## H5 (모바일 웹)로 플레이하기

설치 없이 브라우저에서 바로 돌아간다. 서버와 통신하지 않으므로 한 번 열면 오프라인에서도 계속 플레이된다.

```bash
npm run build:h5
```

`docs/hasukgo/` 에 빌드가 들어간다. 커밋해서 push 하면 GitHub Pages 가 서빙한다.

> https://netbell23.github.io/stocknews/hasukgo/

경로는 상대 경로(`base: './'`)라 어느 하위 폴더에 올려도 그대로 동작한다. 다른 호스팅(Netlify, S3, 사내 서버)에 올릴 때도
`dist/` 를 통째로 복사하면 된다.

### H5 에서 따로 손본 것들

모바일 브라우저는 데스크톱과 다르게 구는 지점이 많아 `src/h5.ts` 에서 한 번에 잡는다.

| 문제 | 처리 |
|---|---|
| 주소창이 접혔다 펴지며 `100vh` 가 실제 화면보다 커짐 | `visualViewport` 를 읽어 `--app-h` 로 내려주고 CSS 가 이걸 쓴다 |
| 아래로 당기면 새로고침돼서 판이 날아감 | 스크롤 영역이 아닌 곳의 당김 제스처만 취소 |
| 더블탭/핀치 확대로 UI가 깨짐 | `touch-action` + 제스처 취소 |
| 카카오톡·라인 인앱 브라우저 | 감지해서 `data-inapp` 속성으로 표시 (레이아웃 보정용 훅) |
| 홈 화면에 추가 | PWA manifest + iOS 전용 메타 태그 |
| 오프라인 플레이 | 서비스 워커가 첫 방문에 받은 파일을 캐시 |

서비스 워커 캐시 이름은 `npm run build:h5` 가 빌드할 때마다 새 값으로 찍는다. 그래서 새 버전을 올리면
이용자 폰에서 자동으로 갱신된다.

> **아직 확인 못 한 것**: 서비스 워커 등록은 개발용 내장 브라우저가 막고 있어 검증하지 못했다.
> 실제 폰이나 크롬에서 한 번 열어 개발자도구 → Application → Service Workers 에 등록되는지 확인이 필요하다.
> 등록에 실패해도 게임은 그대로 돌아간다(오프라인 기능만 빠진다).

## 진행도 저장과 기기 식별

### 왜 폰 고유번호를 쓰지 않았는가

브라우저에는 **IMEI·시리얼번호·MAC 주소를 읽는 API가 아예 없다.** 표준에도 없고 어떤 브라우저도 제공하지 않는다.
Capacitor 네이티브 앱의 `Device.getId()` 도 하드웨어 ID가 아니라 앱 설치마다 새로 생기는 UUID 를 돌려준다.
브라우저 지문(fingerprinting)으로 흉내낼 수는 있지만 Safari·Firefox 가 적극적으로 차단하고,
구글 플레이 정책과 개인정보보호법상 지속적 식별자로 쓰면 문제가 된다.

그래서 **재설정 가능한 기기 ID** 방식을 썼다.

- 첫 실행에 무작위 UUID 를 발급한다. 개인정보를 전혀 담지 않고 어디로도 보내지 않는다.
- 설정 화면에 `HSG-XXXX-XXXX` 형태의 짧은 코드로 보여준다.
- `localStorage` 와 `IndexedDB` 에 이중으로 저장해, 한쪽이 지워져도 다른 쪽에서 되살린다.
- 되살렸을 때는 홈 화면에 알림을 띄운다.

관련 코드: `src/auth/device.ts`

### 백업 코드

서버가 없으므로 진행도 전체를 문자열 하나로 뽑아낸다. 설정 → 진행도 백업에서 복사하거나 파일로 저장한다.

```
HSG1.rZMxb9QwGIb_SvTNThU78SXnDTFUbIhD...(약 700자)....1D3TV4K
```

- 압축(deflate) 후 base64url + 체크섬. 한 글자만 깨져도 거부한다.
- 이 코드를 다른 폰에 붙여넣으면 그대로 이어서 할 수 있다.
- 복원 전에 "무엇을 덮어쓰는지" 요약을 보여주고 확인을 받는다.
- 하숙생이 나중에 추가돼도 옛날 백업 코드를 읽을 수 있다.

관련 코드: `src/save/transfer.ts` / 테스트 `tests/transfer.test.ts`

### 아이폰 사파리 주의

iOS 사파리는 **홈 화면에 추가하지 않은 사이트의 저장 데이터를 일정 기간 뒤 지운다.**
H5 로 오래 즐길 이용자에게는 홈 화면 추가나 백업 코드를 권해야 해서, 설정 화면에도 그 안내를 넣어뒀다.

### 이걸로 할 수 없는 것

이 방식은 **진행도 저장·복구 전용**이다. 아래는 서버 없이는 불가능하다.

- 중복 보상·어뷰징 차단 (기기 ID를 이용자가 초기화할 수 있으므로)
- 기기당 1계정 제한
- 랭킹·업적 같은 공용 데이터

이런 게 필요해지면 서버 + 계정 로그인(카카오/구글) 또는 휴대폰 SMS 인증을 얹어야 한다.

## 데이터 수정법

### 하숙생 고치기 — `src/data/tenants.json`

한 사람의 항목은 이렇게 생겼다.

```jsonc
{
  "id": "eunseo",              // 스크립트 파일명·CG 이름의 접두사가 된다
  "order": 1,                  // 1~10. 난이도 곡선의 한 축
  "name": "은서",
  "nickname": "옆방",
  "age": 22,                   // 전원 성인(22~29)
  "job": "시각디자인과 2학년",
  "room": "201호",
  "season": "spring",          // spring(1~3) summer(4~6) autumn(7~9) winter(10)
  "personality": ["밝음", "덤벙댐", "정 많음"],
  "styleLabel": "아직 규칙을 외우는 중...",   // 선택 화면에 보이는 한 줄
  "style": {                   // 난이도 곡선 위에 곱해지는 고유 성향
    "weights": { "pi": 1.1 },  // gwang/yeol/tti/pi/godori/hongdan/cheongdan/chodan
    "mistakeScale": 1.15,      // 실수 확률 배율
    "greedScale": 1.1,         // 고 성향
    "inferenceScale": 0.8,     // 추론 강도
    "aggressionScale": 0.7,    // 흔들기·폭탄 적극성
    "stopScoreDelta": 1        // 스톱 기준 점수 보정
  },
  "unlock": [],                // 빈 배열이면 처음부터. [{tenantId, stage}] 를 모두 만족해야 열린다
  "reward": { "base": 60, "perStage": 15 },  // 단계 클리어 보상 = base + perStage*(단계-1)
  "entryCost": 20,
  "lines": { ... },            // 상황 8종 × 호감도 3톤 × 3줄 이상 + hints
  "events": [ ... ],           // 단계 1~10, 각 scriptId 는 스크립트 씬 id 와 일치해야 한다
  "look": { ... }              // SVG 입상 생성 파라미터
}
```

대사 톤 구간은 **호감도 0~30 `low` / 31~70 `mid` / 71~100 `high`** 다.
`hints` 는 플레이어가 3연패 중일 때 뜨는 힌트 대사다.

고치고 나면 `npm test` 가 구조를 검사한다 — 대사가 3줄 미만이거나, `scriptId` 에 해당하는 씬이 없거나,
해금이 순환하거나, 보상이 참가비보다 작으면 테스트가 실패한다.

### 시나리오 고치기 — `src/data/scripts/*.txt`

한 파일에 여러 씬이 들어간다. 씬 구분은 `=== id | 제목` 줄이다.

```
=== eunseo_04 | 새벽 두 시의 라면
@bg kitchen night          배경 12종 × 시간대(morning/evening/night)
@bgm warm                  title spring summer autumn winter warm tense sad confess none
@outfit 0                  0 평상복 / 1 외출복 / 2 특별 이벤트복
* 새벽 두 시. 부엌에 불이 켜져 있었다.        ← * 로 시작하면 나레이션
은서 [놀람] 어! 너도 배고팠어?                ← 이름 [표정] 대사
나 소리 나서 내려왔어.                        ← 표정 생략 시 기본
@choice
- 반만 먹자 | +8 | A          선택지: 텍스트 | 호감도증감 | 점프할라벨
- 다 먹어 | +5 | B
@label A
은서 [웃음] 그럼 젓가락 두 개.
@goto END
@label B
은서 [삐짐] 그럼 왜 내려왔어.
@label END
@affection 10              호감도 증감
@point 300                 포인트 증감
@cg eunseo_ending          엔딩 CG 해금
@end                       씬 끝 (필수)
```

**표정 8종**: `기본 웃음 삐짐 놀람 부끄러움 진지 승리 패배`
**배경 12종**: `maru kitchen hallway rooftop yard cvs campus street room annex festival station`

`npm test` 가 스크립트를 전부 파싱해서 문법 오류, 없는 라벨로 점프, `@end` 누락,
`hasChoice` 와 실제 선택지 불일치, 10단계 CG 누락, 무한루프를 잡아낸다.
개발 서버에서는 콘솔에도 경고가 찍힌다.

### 규칙 옵션 — 게임 내 설정 화면

기획서에서 해석이 갈렸던 항목은 임의로 정하지 않고 전부 토글로 만들었다.

- **띠 점수**: 기획서 표기(5장 5점)와 한국 온라인 맞고 표준(5장 1점 + 장당 1점)이 달라 **둘 다** 넣었다.
  기본값은 표준. 홍단/청단/초단 각 3점은 두 방식 모두 동일하다.
- 비삼광 2점 / 3고부터 배수 / 피박 / 광박 / 멍박 / 고박 / 흔들기 / 폭탄 / 총통 / 나가리 2배 / 국진 선택
- 보너스 쌍피 매수 (0~3), 스톱 최소 점수 (3/5/7)

## 아트 교체

지금 캐릭터·배경·화패는 전부 **코드로 생성한 SVG 플레이스홀더**다. 표정 8종이 실제로 다르게 그려지고
게임은 완전히 돌아간다. 원화가 준비되면 파일만 넣으면 된다.

| 종류 | 넣을 위치 | 켜는 법 |
|---|---|---|
| 캐릭터 입상 | `public/art/char/{tenantId}_{outfit}_{expression}.png` | `src/ui/parts.tsx` 의 `IMAGE_FIRST` 를 `true` 로 |
| 배경 | `public/art/bg/{bg}_{time}.jpg` | 같은 파일에서 `Background` 를 수정 |
| 화패 | `public/art/card/{cardId}.png` | 같은 방식 |

`expression` 은 `normal smile sulk surprise shy serious win lose`, `outfit` 은 `0 1 2`.
파일이 없으면 자동으로 SVG 로 되돌아가므로, 한 명씩 순서대로 교체해도 게임이 깨지지 않는다.

캐릭터당 필요한 장수는 **입상 1종 × 표정 8종 × 의상 3종 = 24장**, 10명이면 240장이다.
배경은 12종 × 시간대 3종 = 36장, 엔딩 CG 는 11장(하숙생 10 + 히든 1).

앱 아이콘은 `node scripts/gen-icons.mjs` 로 다시 생성한다.

## 난이도 설계

하숙생 순번(1~10)과 단계(1~10)의 **2차원 곡선**이다. 순번 가중 0.6, 단계 가중 0.4.

- **1번 1단계**: 실수율 50%, 추론 0
- **10번 10단계**: 실수율 0%, 추론 최대 + 플레이어 최근 20판 패턴 학습

패턴 학습은 최상위 구간에서만 켜진다. 플레이어가 고를 자주 하는지, 어떤 항목(광/열끗/띠/피)을
주로 모으는지를 최근 20판에서 뽑아 견제에 쓴다.

AI 대 AI 400~1000판 시뮬레이션으로 검증한 실제 승률:

| 대결 | 승률 |
|---|---|
| 1번 1단계 vs 10번 10단계 | 33% : **67%** |
| 1번 1단계 vs 5번 5단계 | 44% : 56% |
| 5번 5단계 vs 10번 10단계 | 39% : 62% |
| 같은 난이도끼리 | 49% : 51% |

맞고는 배분 운이 크게 작용하는 게임이라 최고 난이도에서도 2:1 정도가 한계다.
그 대신 같은 하숙생이라도 단계가 오르면 눈에 띄게 강해지고, 대사도 "요즘 연습했다"는 톤으로 바뀐다.
`npm test` 의 `tests/balance.report.test.ts` 가 이 표를 매번 다시 뽑는다.

## 진행 구조

```
프롤로그(개강 첫날) → 봄(은서·하영·지우) → 여름(수아·민지·나래)
                    → 가을(예린·세연·도희) → 겨울(윤) → 히든 엔딩
```

- 처음엔 1~3번만 열려 있고, **앞 순번 하숙생의 5단계를 클리어하면** 다음 사람이 열린다.
  윤(최종 히로인)은 예린·세연·도희 세 명의 5단계를 모두 거쳐야 열린다.
- 단계 클리어당 호감도 +10, 이벤트에서 추가로 +10
- **지면 호감도가 깎이지 않는다.** 참가비만 소모되고 다시 도전할 수 있다.
- 3연패하면 해당 하숙생이 힌트 대사를 준다 ("나 요즘 띠만 모으는 거 알지?")
- 전원 10단계 클리어 시 히든 엔딩(마루 단체 사진)

## 톤과 수위

- 등장인물 전원 성인 (22~29세), 15세 이용가 기준의 로맨스 코미디
- 노출·성적 묘사 없음, 도박 미화 없음, 현금 판돈 없음
- **연애는 승부에서 이겨서 "얻는" 것이 아니다.** 승부를 계기로 서로 알아가다 상호 호감으로 이어지는 구조이고,
  모든 10단계 고백 대사에 "이겨서 받는 상이 아니다"라는 취지가 명시돼 있다.
- 지면 하숙생이 실망하는 게 아니라 다음 승부를 기대하는 톤으로 쓰여 있다.

## 알려진 한계

- 아트는 전부 플레이스홀더다. 게임성 검증에는 충분하지만 상용 수준의 일러스트는 아니다.
- BGM/효과음은 태그만 스크립트에 들어가 있고 실제 음원은 없다. `ScenarioView.bgm` / `sfx` 를 읽어 재생기를 붙이면 된다.
- 수익화(광고 보상, 스킨 상점)는 화면 자리와 포인트 구조만 잡아뒀고 결제 연동은 없다.
- 서비스 워커(오프라인 캐시) 등록은 실제 폰에서 한 번 확인이 필요하다. 개발용 내장 브라우저가 막고 있어 검증하지 못했다.
- APK 빌드는 GitHub Actions 에서 검증해야 한다. 이 저장소에서 아직 워크플로를 한 번도 돌리지 않았다면
  첫 실행에서 툴체인 문제가 나올 수 있다(AGP 8.7.2 / Gradle 8.9 / JDK 17 / compileSdk 35 조합으로 맞춰뒀다).
